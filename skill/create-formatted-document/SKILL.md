# Create a formatted document

Deliver the actual document the reader can use and the author can maintain. An outline or a collection of suggested sections is only an intermediate result unless that is what the user asked for. Let the document's purpose determine its content and layout rather than fitting every request into the same report template.

Keep the substantive task primary. When the request is to analyze data, make a proposal, synthesize research, or explain a technical system, use that purpose-specific workflow and apply document construction only as needed for the requested artifact. A DOCX requirement alone does not turn those tasks into formatting assignments. This guide is primary when assembling the complete document from the supplied material is the main work, as with a handbook or reusable report template.

## Establish what the document must do

Use the request and supplied material to identify the reader, purpose, required content, requested file type, and intended reading or printing context. Preserve explicit choices such as a template, page size, length, required headings, tone, or editable fields. Resolve only questions that materially change the result; choose ordinary layout details and proceed when the brief supports them.

Distinguish a new filled document from a reusable template. A finished handbook needs the supported instructions themselves, not prompts telling the user to write them. A reusable template needs clear replacement fields and a structure that survives ordinary edits; any demonstration content must be recognizably illustrative. Do not invent an organization, policy, approval, quotation, contact, or operating procedure to make either appear complete.

When an existing template is supplied, inspect its structure and native features before authoring. Determine which parts are fixed and which are intended for replacement. Keep required styles, headings, fields, table relationships, and branding. A previous report can be a layout reference without making its old facts authoritative. If the task is actually to revise a supplied draft or fill a fixed form, keep that narrower task primary.

Read the relevant sources far enough to understand their conditions and relationships, including useful tables, captions, and notes. Keep approved facts separate from proposed content and unresolved decisions. Continue supported sections when one point is missing. Put an unresolved fact where the reader needs it or identify it precisely in the handoff; do not scatter unexplained placeholders through otherwise finished prose.

## Build the reading structure and content together

Organize around how the audience will use the document. A newcomer handbook may need an orientation followed by tasks and reference details. A report may need its answer before the supporting analysis. A template may need a small amount of embedded guidance that future authors can remove. Use the requested structure when supplied; do not impose an executive summary, contents page, appendix, or approval section on a short document.

Write complete content at the intended level of detail. Connect facts into explanations, instructions, or arguments appropriate to the purpose. Make a procedure's prerequisites and exceptions available before a reader takes the affected step. Keep estimates, conditions, units, dates, and attribution attached to the claims they qualify. Preserve exact quoted language and required strings. Include source references where the reader needs to verify or reuse a claim, without turning every sentence into a source ledger.

Choose a table when row and column relationships help the reader compare or locate information. Keep its headers, units, notes, and cell associations unambiguous. Use lists for genuine steps or parallel items, not as a substitute for connected explanation. Use a visual only when it communicates something the document needs; ensure its caption and surrounding text agree with its contents.

Before polishing layout, check the document as a whole: does the reader have enough information to accomplish the stated purpose, and does each included section contribute? Remove duplicated instructions and unsupported filler. A polished title page does not compensate for missing operative content.

## Author the editable artifact

Use an available tool that supports the requested native format. Preserve text as text, tables as editable tables, and images at useful resolution. Do not present page screenshots embedded in a document as an editable result.

Apply a small, consistent style system through native document features where supported:

- Use real heading levels and list numbering so navigation and later edits remain coherent
- Set spacing, indentation, typography, and recurring elements through styles rather than manual blank lines or runs of spaces
- Use intentional page or section breaks when needed; allow ordinary body text to flow without forcing every paragraph onto a fixed page
- Keep headings with their related content, and make long tables understandable across page boundaries
- Give links meaningful labels and the correct destinations; keep captions, notes, and cross-references attached to their subject

Match typography and contrast to the reading context. Prefer fonts available to the chosen authoring and rendering tools, and inspect special characters, long identifiers, and dense tables. If a required font is unavailable, make any material substitution visible instead of claiming an exact match. Use helpful structural and alternative-text features when supported; their presence alone does not establish accessibility conformance.

For a template, distinguish editable inputs from fixed guidance without making normal editing cumbersome. Use native controls only when the requested format and available tool support them. Test a representative replacement, such as a longer title or an additional table row, in a separate copy when reuse depends on that behavior. Restore a clean template before delivery. Do not call an ordinary bracketed placeholder a functioning control.

Save the native document to the authorized destination. Keep source material and unrelated files intact. If a PDF or another export was requested, produce it from the same final document revision; do not leave the editable source and its export describing different content.

## Inspect the saved result

Reopen the exact saved file. Confirm the substantive content and native structure, including required headings, table associations, links, images, and any fields or controls the reader will use. A successful save or text extraction does not establish a readable layout.

Render or inspect every page of a paginated document when the available tools support it. Look at normal reading size, with closer inspection where needed for tables, footnotes, symbols, headers, or page breaks. Repair clipping, overlap, missing glyphs, awkward empty pages, detached headings, and unreadably dense content. Recheck affected content and pagination after a repair. For a reflowing document, inspect the relevant view and state the scope rather than claiming a fixed page layout.

Check any requested export as its own saved file. At minimum, confirm that intended content, order, meaningful links, and visible layout survived. Use more detailed conversion checking when the document's features or the request require it. Do not infer compatibility with another application from a single renderer, or claim link interaction, edit/save behavior, or accessibility checks that did not run.

If native authoring or rendering is unavailable, finish the supported work and name the exact missing deliverable or check. A useful draft can be handed over with that limit, but plain text must not be labeled a created Word file and an unseen export must not be called visually checked.

## Hand over the usable document

Return the saved editable document and any requested exports or verified destination link. Briefly identify material assumptions, remaining content decisions, and relevant verification limits. Small documents need a small handoff; the user should not have to read a production log to find the file.

Creating the document does not itself authorize sending it to another person or changing its audience. Complete any delivery already requested within its approved scope, and verify the actual saved or delivered result rather than treating local creation as proof of a remote save.
