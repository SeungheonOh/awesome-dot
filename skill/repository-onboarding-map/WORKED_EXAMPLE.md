### `app/labels.py`

```python
def make_label(title, prefix):
    words = title.strip().lower().split()
    if not words:
        raise ValueError("title must contain a word")
    return prefix + ":" + "-".join(words)
```

### `app/cli.py`

```python
import argparse

from app.config import read_prefix
from app.labels import make_label


def build_parser():
    parser = argparse.ArgumentParser(
        prog="waymark", description="Print a normalized local label."
    )
    parser.add_argument("title")
    return parser


def main():
    args = build_parser().parse_args()
    print(make_label(args.title, read_prefix()))


if __name__ == "__main__":
    main()
```

### `tests/test_labels.py`

```python
import unittest

from app.labels import make_label


class LabelTests(unittest.TestCase):
    def test_words(self):
        self.assertEqual(make_label(" Blue  Sky ", "note"), "note:blue-sky")

    def test_empty(self):
        with self.assertRaises(ValueError):
            make_label("   ", "note")
```

### `tools/render_help.py`

```python
from pathlib import Path

from app.cli import build_parser


if __name__ == "__main__":

    output.write_text(
```

### First local task: add the missing tab case

Acceptance condition: `make_label(" Blue\tSky ", "note")` returns `note:blue-sky` and has a named unit test beside `test_words`.

Read `app/labels.py:2–5`, then add the assertion under `LabelTests` in `tests/test_labels.py:6–12`. The existing `split()` already expresses whitespace separation, so the proposed task is test coverage, not a request to change normalization behavior. Run the already-verified `make check` from the repository root after the edit. Expected touched file: `tests/test_labels.py` only. No generated help refresh is needed because the argument contract is unchanged.

Baseline: the existing two tests passed, and the checker separately called `make_label` with the proposed tab input and observed the expected result. That direct assertion confirms current behavior in this fixture, but it does not pretend the new named test has been added. The proposed change is unimplemented; this deliverable establishes its reading/edit/check route.
