F8 — Repair Fieldcard's local merge consumer

I maintain Fieldcard, a fictional offline editor for short equipment instruction cards. Repair the supplied Python merge session and its real JSON save/reload caller. Two bugs have been reported: a chosen conflict alternative is reused after the source revision changes, and saving a card with unresolved conflicts labels it complete and overwrites the last completed text. This is a bounded maintenance task, not a request to build a diff engine.

Text model and merge rule
The protected merge_primitive.merge_lines(base, left, right) is a working minimal primitive. Use it or implement equivalent behavior in an editable file; do not edit the primitive. A supported text is a nonempty Python str, contains no CR, ends with LF, and has 1 through 12 positional lines. The final LF is a delimiter, not an extra line. A further LF represents an actual empty line. Empty lines, leading/trailing spaces within lines and Unicode are significant; do not normalize them. All three texts in one comparison have the same line count. Matching is strictly by zero-based line index; there is no insertion/deletion matching, fuzzy matching, or content-based relocation. A replacement set may use a different common line count.
For each line with base B, left L, right R: if L == R, use L; otherwise if L == B, use R; otherwise if R == B, use L; otherwise that line is a conflict. Every automatic line appears unchanged in the result. At an unresolved conflict, use the base line in the draft text. At a resolved conflict use the chosen side's exact line. Rejoin all lines with LF and retain the final LF. A conflict stays represented in the conflict list even after a choice resolves it. There is exactly one conflict record per conflicting positional line, ordered by index. These deliberately fixed units are part of this application's supported API.

Source identity and revisions
A source is a dictionary with exactly document_id, revision and text. document_id is a nonempty str, revision is a nonnegative int (not bool), and text follows the text model. Base, left and right have the same document_id. Revisions belong to their individual source snapshots: the revision numbers need not be distinct or increasing across the three branches. An existing session/editor cannot switch document_id. reject such a replacement with ValueError without changing state. Other invalid source inputs are also rejected with ValueError without changing an existing session.
Snapshot all input dictionaries; later mutation of a caller's dictionaries must not silently alter stored sources. A source set is identical only if every document_id, revision and text value on all three sources is identical. Calling replace_sources with an identical set preserves choices and generation. Any other valid change, including a revision-only change, a text-only change with the same revision, a base change or a common line-count change, increments the generation once and discards ALL prior choices. No prior choice may migrate by line index or by coincidentally matching alternatives. This conservative invalidation policy is intentional.

Supported public API (preserve these names and keyword parameter names)
merge_session exports StaleChoiceError, a subclass of ValueError, and MergeSession:
- MergeSession(base, left, right) creates a session at integer generation 0 with no choices
- replace_sources(base, left, right) implements the replacement rule above
- choose(index, side, generation) accepts side "left" or "right" for a current conflict index. It records/replaces that choice. It must first reject a generation token unequal to the current generation, or a token whose type is not exactly int (bool included), with StaleChoiceError and no state change. A current-generation call with an invalid side or non-conflict/invalid index raises ValueError and changes nothing
- view() returns a detached dictionary with exactly these keys: document_id, generation, status, text, conflicts. status is exactly "draft" when any conflict lacks a choice, otherwise "complete". conflicts is the ordered list of dictionaries with exactly index, base, left, right, choice. base/left/right are the exact line strings from the current source snapshots, without their LF delimiters; choice is null/None, "left" or "right". Automatic lines do not appear in conflicts. text is the merge text defined above
- to_state() returns detached JSON-compatible state with schema=1, sources={base: source, left: source, right: source}, generation, and choices=[{index: integer, side: "left" or "right"}, ...] ordered by index. It contains exactly the current choices and snapshots. Preserve these fields; extra JSON-compatible extension fields are allowed
- MergeSession.from_state(state) restores any state previously produced by a conforming to_state(), preserving snapshots, choices and generation. Mutating the state argument afterward must not change the restored session. No recovery policy for hostile/corrupt JSON is required

card_editor exports CardEditor:
- CardEditor(base, left, right) owns a MergeSession and initially has no last completed save
- replace_sources(base, left, right), choose(index, side, generation), view() expose exactly the session behavior through this actual consumer. Its public session attribute remains a MergeSession
- save(path) writes a UTF-8 JSON file to the supplied local path and returns a detached dictionary equal to the parsed file. Required record fields are format=1, session=session.to_state(), status=view()["status"], text=view()["text"], completed_text. Extra JSON-compatible extension fields are allowed
- On a complete save, completed_text becomes the exact current text. On a draft save, completed_text remains the exact text from the most recent complete save on this editor or an editor restored from it. If no complete save exists, it is null. The old completed text can coexist with a newer draft from the same document; label that draft "draft". Never auto-choose, discard pending conflicts or promote base fallback text to completed text when saving
- CardEditor.load(path) returns an editor restored from a conforming save. Its view, source state, generation, choices and last completed save must survive a JSON file round trip. A loaded draft remains draft; selecting remaining conflicts and saving can then produce a complete record. A loaded complete card can be revised and saved as a draft without losing the previous completed_text
- save/load support pathlib.Path and str paths. Parent directories exist. Atomic filesystem crash recovery and malformed-file recovery are outside scope
