# Exhibition Label System

Create a consistent label system that explains exhibits without overstating claims or exposing confidential work.

## Scenario

Your workplace is hosting a demo afternoon with prototypes, diagrams, and small physical models. Visitors range from engineers to nontechnical guests. You need labels that explain the work clearly, distinguish working features from concepts, and keep confidential customer examples or internal project details out of view.

## Inputs to prepare

- Approved exhibit descriptions, creator credits, and demonstration status
- The intended audience, venue visibility, and confidentiality exclusions
- Label sizes, viewing distance, and brand guidance
- Authorized supporting images and any verified links or optional codes

## Copy this prompt into dot

```text
dot, design an exhibition-label system for [DEMO EVENT OR EXHIBITION] using [APPROVED EXHIBIT DESCRIPTIONS]. The audience is [VISITORS], the venue visibility is [PUBLIC OR INTERNAL SCOPE], and [CONFIDENTIAL MATERIAL] must be excluded. First identify what each exhibit actually demonstrates, what remains a concept, and which claims need owner confirmation. Do not invent performance results, customer endorsements, creator credits, or working features.

Create three related label types: a short object label, a fuller explanation panel, and a section introduction. Use [LABEL DIMENSIONS] and [VIEWING DISTANCE]. Give non-specialists a plain-language opening sentence, then optional technical detail. Keep demonstration status visible and explain unfamiliar terms from supplied information. Use editable text and readable contrast; place any approved link or code separately from decorative imagery.

Deliver label masters or a full specification, populated review examples, an exhibit-to-label register, and an installation checklist. Test the longest title, a multi-creator credit, a concept with no working prototype, and a label read from the intended distance. Verify every destination link and state if code scanning was not tested. Keep the drafts private. Do not publish, expose internal links, print for installation, or place labels in a public venue until exhibit owners approve the claims, files, and audience.
```

## Iterate with a purpose

### 1. Simplify visitor language

```text
Review each opening sentence for an unfamiliar visitor and propose plain-language alternatives without adding capabilities or claims.
```

### 2. Audit demonstration status

```text
Check every label against the supplied status record and make the distinction between concept, prototype, and demonstrated feature explicit.
```

### 3. Prepare installation map

```text
Create a label-to-exhibit placement map with revision identifiers and a final owner-review checklist without authorizing installation.
```

## Expected deliverables

- Three related label masters or specifications
- Populated review examples
- Exhibit-to-label and claim register
- Link and legibility test notes
- Installation approval checklist

## Acceptance checks

- Every label maps to an approved exhibit and owner
- Concepts are not described as demonstrated features
- A long title and multi-creator credit fit legibly
- Confidential examples and internal-only destinations are excluded from public drafts
- Links match verified user-approved destinations
- Untested code scanning is disclosed

## Access, privacy and stop conditions

- Design output does not validate prototype claims or performance
- Label editing and export depend on available tools
- Confidential assets require an explicit audience boundary
- Public display, printing, and publication require final owner approval

## Two possible extensions

- Create an accessible text companion for the exhibition
- Prepare a visitor-feedback card using approved questions
