# Choose a learning path

These paths build working habits, not account entitlements. Start with the smallest task that produces something you can inspect. A later step may require additional tools or access.

## Path 1: an engineer's first week with dot

1. Complete the [fictional bug-report exercise](WORKPLACE-QUICKSTART.md)
2. Reframe one sanitized work request using the [task-brief template](TASK-BRIEFS.md)
3. Ask for a source-grounded explanation or read-only investigation before requesting changes
4. Review facts, assumptions, edge cases and unrun checks
5. Record one real result with the [run log](../templates/RUN-LOG.md)

The goal is to learn when dot's output is useful and what evidence you still need, not to automate every step immediately.

## Path 2: from an idea to an interactive prototype

Start with one web-game or creative-coding recipe in the [catalog](../CATALOG.md). Ask for one complete mechanic or interaction, then test reset, empty states, repeated input and keyboard use. Add polish only after the core behavior works. Keep the prototype private until you decide to publish it.

## Path 3: from visual concept to usable asset

Choose an image-editing or design/publishing recipe. Begin with authorized inputs and a clear destination format. Inspect the actual output at its intended size. Verify text, edges, contrast and export properties. Move to a 3D/spatial recipe only when the needed modeling or rendering software is available.

## Path 4: from research to a decision brief

Choose a news/research or finance recipe. Define the time window, source expectations, assumptions and output audience. Verify one important claim or calculation yourself. Keep disagreements and unknowns visible. Use financial outputs for education and planning, not autonomous transactions or individualized investment recommendations.

## Path 5: from a plan to a bounded reminder

Choose a personal-reminder recipe. Start with one explicit reminder, your personal timezone and a known delivery destination. Confirm the actual setup and next run. Only then consider a recurring task with an end date or stopping condition. A written schedule is not an active reminder.

## Path 6: help another dot agent use the collection

Read [AGENT-GUIDE](AGENT-GUIDE.md), choose a recipe by desired outcome, and pass only the relevant inputs and scope. Keep the recipe's boundaries and checks intact. Treat examples as reference material rather than authorization to act.
