# Plain-language glossary

| Term | In this collection |
| --- | --- |
| dot | The assistant you ask to help with a task; actual capabilities depend on available access and tools |
| Prompt | The message you give dot, ideally with a goal, inputs and checks |
| Recipe | A proposed project guide, not a preinstalled feature or a working demonstration |
| Artifact | A concrete output such as a document, image, spreadsheet, code project or model file |
| Context | Information dot needs to understand the task correctly |
| Connected app | An external account or service made available for supported actions |
| Computer access | Permission and availability to work in a specific computer environment |
| Toolchain | The software needed to create, run, inspect or export a project |
| Prototype | A small version used to learn or test an idea before committing to a larger build |
| Acceptance check | An observable test of whether the result meets a requirement |
| Edge case | An unusual but plausible input or action, such as no results or a repeated click |
| Source-grounded | A claim supported by identifiable supplied or retrieved evidence |
| Inference | A conclusion drawn from evidence, which should be distinguished from an observed fact |
| Hallucination | A plausible-sounding claim or artifact detail that lacks adequate support |
| Iteration | A focused revision in response to a specific gap, check or new requirement |
| Read-only | Inspecting or analyzing without changing the external source |
| Synthetic data | Invented example data that does not describe real people or accounts |
| Sanitized data | Real material with unnecessary or sensitive details removed or replaced |
| Timezone | The location-based time rules used to interpret a schedule, including daylight saving changes where applicable |
| Polling | Checking a source repeatedly at intervals, rather than receiving an event as it happens |
| Scheduled task | Future work whose actual timing and enabled state must be confirmed |
| Front matter | A small metadata block at the top of a Markdown file, useful for navigation and automated checks |
| Markdown | Plain text with simple formatting such as headings, links, lists and code blocks |
| Not run | A check or project that has not been executed; it is neither a pass nor a failure |
